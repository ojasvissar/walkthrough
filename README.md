# WalkThrough

WalkThrough turns a GitHub codebase into a walkable Three.js building. Floors represent layers, rooms represent modules, and illuminated paths represent imports. Inspect rooms and their function exhibits to learn where things live in the code.

## Run locally

Install Node.js and npm, then run these commands from the repository root.

```sh
npm ci
npm start
```

Open [WalkThrough on localhost](http://127.0.0.1:8765). Use **Orbit** for the full building or **Play** to explore as Codex, the man, or the woman. Move with WASD or the arrow keys, hold Shift to run, drag to look, and press E to inspect a room. The sun and moon control the appearance.

Start with `WALKTHROUGH_CODEX=1 npm start` to enable the authenticated local Codex CLI. You can also serve `public/` with a static file server for the browser demo.

## Demo

1. **Explore.** Paste a public GitHub URL, choose a saved example, or import architecture JSON. Start the **90-second tour** or use the quiz to check recall.
2. **Trace login.** Sign in to The Tiny Shop. Enable slow lookup to see the request wait in User Store.
3. **Break it.** Run the login test against an isolated copy with one line changed. Watch the request fail in Auth Service.
4. **Repair.** Let the local Codex runtime propose a fix and run the same test. Download the patch or open an optional GitHub draft PR.

**Backup film** plays the bundled replay of the trace, test failure, and repair.

| Saved example | Tour |
| --- | --- |
| [Full Stack FastAPI](https://github.com/fastapi/full-stack-fastapi-template) | React sign-in, Python routes, authentication, and data models |
| [Express](https://github.com/expressjs/express) | JavaScript request handling and rendering |
| [Flask](https://github.com/pallets/flask) | Python dispatch, templates, and sessions |
| [Vite](https://github.com/vitejs/vite) | CLI, dev server, plugins, and build |

The saved examples are available offline. The Tiny Shop powers the live acts.

## Analyze a repository

The workspace can scan a public GitHub repository directly. For a local checkout, use the authenticated Codex CLI to generate an architecture map.

```sh
node scripts/map-repository.mjs /path/to/checkout architecture.json
```

Load it via **Example repos → Import architecture JSON**. The format is defined in the [architecture schema](schemas/architecture.schema.json). **Git replay** animates the repository’s recent commits or the imported history.

**Ask the building** answers questions with file and line citations. Attach JS, TS, or Python files to make local source available to an imported map. The local presenter uses the authenticated Codex CLI with `WALKTHROUGH_CODEX=1`, or an `OPENAI_API_KEY` supplied through its environment. The hosted Worker uses a Sites runtime secret. Submitting a question passes relevant source excerpts to the configured answer provider.

## Audience mode

Run `WALKTHROUGH_AUDIENCE=1 npm start` and choose **Audience** for the QR code. Guests on the same network can move a dot in the building. The guest server defaults to port 8767. Set `WALKTHROUGH_AUDIENCE_ADDRESS` to the presenter’s LAN address if automatic detection selects the wrong interface.

## Draft repair PR

Use a repository and base branch you control. In that branch, the lowercasing fault replaces `return value.trim().toLowerCase();` with `return value.trim();` in [`public/js/shop/auth.js`](public/js/shop/auth.js).

Sign in to the GitHub CLI and start the presenter with the repair target.

```sh
WALKTHROUGH_CODEX=1 WALKTHROUGH_PR_REPO=owner/repository WALKTHROUGH_PR_BASE=demo-broken npm start
```

Use `WALKTHROUGH_PR_FILE` if the demo is under a subdirectory or the target branch still uses the older auth path. After a passing repair, **Open draft PR** shows the target and lets you publish the draft.

## Checks and build

```sh
npm test
npm run build
```

The build packages `public/` into `dist/server/index.js` for the hosted Worker.

Avatar rigs follow the [Codex 3D Asset voxel preset](https://github.com/anisayari/codex-3d-asset/blob/main/data/style-presets.json). The picker portraits are generated by [`scripts/render-avatar-icons.mjs`](scripts/render-avatar-icons.mjs). The backup film uses events from [`scripts/capture-demo-traces.mjs`](scripts/capture-demo-traces.mjs), frames from the [Pillow renderer](scripts/render-demo-replay.py), and FFmpeg encoding.
